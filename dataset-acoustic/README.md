# Acoustic Dataset Directory (`dataset-acoustic/`)

This directory holds every acoustic-related material for the Onion Quality &
Freshness Grading project, strictly separated by verification status.

## Headline status (read this first)

**No publicly downloadable, redistributable onion acoustic dataset was found.**
The only onion-specific vibrometry study located is a journal paper whose
underlying audio/vibration data is not published (see `research/`). The only
downloadable related-produce acoustic dataset found (coconut tapping,
Mendeley Data) is CC BY-NC-ND and its single 278 MB XLSX file exceeds GitHub's
size limit — it is **not redistributed here**; only its metadata and a manual
download script are included.

Therefore:

- `raw/` and `processed/` are **empty except for placeholder READMEs**.
  They are reserved for future **verified onion recordings** collected with the
  protocol in `collection_protocol.md`.
- `research/` contains the paper metadata and protocol design notes (no
  paper PDFs — see licensing note in `SOURCES.md`).
- `auxiliary/` contains metadata for the related-produce dataset (not the data).
- `synthetic/` contains the clearly-labelled synthetic demonstration audio
  described below. **It is not onion data and must never be used as onion
  ground truth.**

## Dataset-type labels used everywhere in this project

| Label | Meaning |
|---|---|
| `verified_onion_acoustic` | Real onion recordings with verified internal ground truth — **none exist yet** |
| `related_produce_acoustic` | Acoustic data from other produce (e.g. coconut) — signal-processing reference only |
| `generic_audio_pretraining` | Generic impact/environment audio — pipeline testing only, never onion labels |
| `paper_only` | Study exists as a paper; no downloadable data |
| `synthetic` | Programmatically generated audio — demo/pipeline testing only |

## Directory layout

```
dataset-acoustic/
├── README.md               <- this file
├── SOURCES.md              <- every source, incl. "Not redistributed" section
├── LICENSES.md             <- license status of every source; no invented licenses
├── MANIFEST.csv            <- every file in this directory tree
├── checksums.sha256        <- SHA-256 of every file in this directory tree
├── collection_protocol.md  <- phone-only capture protocol (how to collect real data)
├── metadata_schema.json    <- per-recording metadata schema (single source of truth)
├── raw/                    <- verified raw onion recordings (EMPTY — awaiting collection)
├── processed/              <- derived features from verified recordings (EMPTY)
├── research/               <- paper metadata and reference notes
├── auxiliary/              <- related-produce metadata (data itself NOT redistributed)
├── synthetic/              <- clearly-labelled synthetic demo audio
└── parts/                  <- GitHub-safe part directories (whole files only)
```

## What the synthetic data is (and is not)

`synthetic/demo_chirp_responses/` contains 16 short WAV files generated by a
documented script (`tools/generate_synthetic_acoustic_demo.py`) with two
classes ("firm-like", "defect-like") based on published ranges of resonance
behaviour in produce. They exist to:

1. exercise the DSP pipeline end-to-end (loading, QC, features, export);
2. smoke-test the acoustic training script;
3. provide audio for the demo script without any license constraints.

They do **not** come from onions, do not include room acoustics, phone speaker
or microphone characteristics, and prove nothing about onion internal defects.
Every file carries `synthetic` in its name, and `MANIFEST.csv` labels every
row `synthetic`.

## How to add real data later

1. Follow `collection_protocol.md` (phone-only capture, per-onion IDs,
   ambient baseline, cut-open ground truth).
2. Place recordings in `raw/` and run the feature exporter into `processed/`.
3. Fill one metadata JSON per recording per `metadata_schema.json`
   (`dataset_type: verified_onion_acoustic`, real `ground_truth_method`).
4. Re-run `tools/prepare_acoustic_dataset.py` to rebuild `parts/`,
   `MANIFEST.csv`, and `checksums.sha256`.
5. Only then may any acoustic model be presented as trained on onion data.
